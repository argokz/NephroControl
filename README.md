# НефроКонтроль

Калькулятор СКФ для контроля лечения пациентов с хроническим пиелонефритом, сахарным диабетом и пневмонией.

Это инструмент поддержки решений врача: он считает СКФ, стадию и сроки контроля и показывает предупреждения со ссылками на источники. Диагноз и назначения остаются за врачом. Приложение не проходило клинической оценки. Часть правил имеет статус «требует сверки» (см. [список](#правила-со-статусом-требует-сверки)).

## Запуск

Нужен Node.js 20.19+ или 22.12+ (требование Vite 8).

```bash
npm install
npm run dev        # dev-сервер, http://localhost:5173
npm test           # тесты (Vitest)
npm run typecheck  # проверка типов (vue-tsc, strict)
npm run build      # проверка типов + сборка в dist/
npm run preview    # просмотр собранной версии
```

Сборка в `dist/` — статические файлы, их можно отдать любым веб-сервером. Сервер приложению не нужен: все данные хранятся в браузере (IndexedDB).

### Данные и конфиденциальность

- Пациент заводится под псевдонимом или номером карты, без ФИО.
- История хранится только в том браузере и профиле, где её ввели. Очистка данных сайта в браузере удаляет историю. Резервного копирования и импорта нет — для сохранения используйте экспорт CSV.
- На общем компьютере история видна всем, кто открывает приложение в том же профиле браузера.

## Возможности

- **Расчёт.** CKD-EPI 2009 (основная, определяет стадию), CKD-EPI 2021 (справочно), клиренс креатинина по Кокрофту–Голту. У каждого числа указана формула, у CrCl — какая масса тела использована.
- **Классификация.** Стадия С1–С5, категория альбуминурии А1–А3, риск по сочетанию С×А, срок следующего анализа.
- **Предупреждения.** Общие правила (недостоверность формулы, пороги госпитализации, ОПП) и правила групп. Предупреждения разделены на «Экстренно», «Важно», «Информация». У каждого — источник [И1]–[И8] и статус.
- **История и динамика.** График eGFR с границами стадий, таблица анализов. В таблице — изменение к предыдущему и к первому значению, оценка «значимое ухудшение» или «улучшение», сработавшие правила, версия `rules.json`.
- **О программе** (вкладка или ссылка `…/#about`). Как работает программа, формулы, таблицы классификации и полный список правил — всё строится из `rules.json`. Там же источники, допущения и **самопроверка**: эталоны и сценарии раздела 13, свойства формул и границы порогов выполняются прямо в браузере тем же кодом, что и расчёт.
- **Сверка с лабораторией.** Сравнение eGFR приложения со значениями из бланков лаборатории на обезличенной выгрузке — см. раздел «Сверка с лабораторией» ниже.
- **Экспорт.** CSV (разделитель «;», десятичная запятая — открывается в русскоязычном Excel) и печатная форма.

## Архитектура

Vue 3 (Composition API) + TypeScript strict + Vite; тесты — Vitest; график — Chart.js; хранилище — IndexedDB через `idb`.

```

    rules.json          все пороги, тексты сообщений, источники и статусы правил
    rules.ts            загрузка и проверка rules.json при старте
  core/                 чистая логика: без Vue, DOM и хранилища
    types.ts            типы ввода, правил, результатов и записей истории
    ruleBook.ts         доступ к правилам по id, подстановка {параметров} в тексты

    formulas/           CKD-EPI 2009, CKD-EPI 2021, Кокрофт–Голт, ИМТ, масса по Devine
    classification.ts   стадия, альбуминурия, риск, срок следующего анализа
    validation.ts       проверка ввода

    labCompare.ts       сверка с лабораторией: разбор CSV, разница, пределы согласия, стадии, каппа
    verification.ts     самопроверка: эталоны и сценарии ТЗ (страница «О программе» и тесты)
  config/evidence.ts    страницы официальных PDF, подтверждающие правила
  storage/db.ts         IndexedDB: пациенты и анализы
  ui/                   компоненты Vue: форма, результат, предупреждения, история, график
```

### Поток расчёта

1. `validateInput` проверяет ввод. Ошибки блокируют расчёт; предупреждения, например о нетипичной единице креатинина, — нет.
2. Креатинин переводится в мг/дл. Считаются eGFR 2009 и 2021 и CrCl. При ИМТ ≥ 30 основной CrCl считается по скорректированной массе, по фактической — дополнительно.
3. Стадия определяется по eGFR 2009, округлённой до целого — то есть по тому же числу, что видит пользователь. Все пороги eGFR в правилах сравниваются с этим же значением.
4. `evaluateRules` собирает контекст: текущий анализ и предыдущие анализы пациента. Предыдущими считаются записи с датой забора *раньше* текущей, а не записи, введённые раньше, — поэтому анализ можно внести задним числом. Затем запускаются общие правила, правила динамики и правила выбранных групп. Результаты сортируются: экстренные → важные → информационные.
5. При сохранении в историю пишутся исходный ввод, сырые значения формул, стадия, id сработавших правил и версия `rules.json`.

### rules.json

Каждое правило:

| Поле | Содержание |
|---|---|
| `id` | идентификатор, на который ссылается код |
| `value` | порог или таблица |
| `unit` | единица значения |
| `message` | текст для пользователя; `{name}` подставляется при выводе |
| `source` | массив ссылок на источники И1–И8 |
| `status` | «проверено» или «требует сверки» |
| `severity` | `emergency` / `important` / `info` — для правил, которые выводятся как предупреждения |
| `labels` | подписи (стадии, уровни риска, особые состояния) |
| `note` | пояснение; допущения начинаются с «Допущение:» |

Код не содержит клинических порогов и текстов — только id правил (`RULE_IDS` в `ruleBook.ts`). При старте конфиг проверяется: каждый id из кода должен быть в JSON, источники — только И1–И8, статус — одно из двух значений. Если проверка не проходит, приложение не запускается. Чтобы изменить порог или формулировку, достаточно отредактировать `rules.json` и поднять `version`: версия сохраняется в каждой записи истории.

Отсюда следует ограничение: старые записи истории не пересчитываются при смене версии правил. В них остаются стадия и сработавшие правила на момент сохранения.

## Расхождения с ТЗ и источниками

По разделу 11 ТЗ опечатки и неоднозначности не исправлены молча, а описаны здесь и в комментариях к коду.

1. **Опечатки в упрощённой таблице CKD-EPI 2009 в тексте [И1].** Сверено с официальным текстом [И1]: в строках для мужчин напечатан множитель 144 вместо 141, в первой строке — «СКр/0,0», во второй — «СКр/0,7» вместо «СКр/0,9». Как требует ТЗ (5.1), реализована общая формула (`src/core/formulas/ckdEpi2009.ts`), таблица не используется.
2. **Расовый коэффициент удалён.** ТЗ (5.1) предусматривало коэффициент × 1,159 как настройку, выключенную по умолчанию. По решению от 29.09.2026 он не реализован ни в коде, ни в конфиге: глобальная настройка применялась бы ко всем пациентам, а в данных пациента нет и не должно быть признака расы; [И8] от коэффициента отказывается. Тест из раздела 13 про коэффициент заменён тестом «формула не содержит расового множителя».
3. **Граница С1.** В тексте [И1] записано «> 90», в таблице ТЗ — «≥ 90». Значение ровно 90 отнесено к С1, как требует ТЗ; правило `stage.bounds` — «требует сверки».
4. **Округление.** ТЗ требует округлять итог только при выводе, но не определяет, по какому значению ставится стадия. По решению от 29.09.2026 стадия и все пороги eGFR сравниваются с округлённым до целого значением (`stage.rounding`). Иначе при 89,6 на экране было бы «90», а стадия — С2.
5. **Коэффициент Devine.** В ТЗ — 0,9 кг/см. Это округление исходных 2,3 кг на дюйм (≈ 0,9055 кг/см). Реализовано как в ТЗ, при росте 190 см идеальная масса получается примерно на 0,2 кг меньше.
6. **CrCl при ИМТ ≥ 30.** ТЗ требует считать по скорректированной массе «дополнительно». По решению от 29.09.2026 основным считается CrCl по скорректированной массе, по фактической — дополнительный; в истории пишется, какая масса использована.
7. **Перекрёстная ссылка в 7.1.** ТЗ ссылается на «быстрое снижение функции (см. 7.3)», но быстрое снижение (удвоение креатинина) описано в 7.2, а в 7.3 — ОПП. Недостоверность формулы выводится в обоих случаях.
8. **Единицы САК.** Пороги в мг/ммоль (3; 30) и мг/г (30; 300) после пересчёта не совпадают: 3 мг/ммоль ≈ 26,5 мг/г. Поэтому САК классифицируется в тех единицах, в которых введено, без пересчёта.

12. **Эталон 2 раздела 13.** Для креатинина 71 мкмоль/л CKD-EPI 2021 даёт 92,1; в таблице ТЗ — 93. Разница в пределах допуска ±1, стадия (С1) не меняется. Тест сравнивает с табличным значением 93 с допуском ±1.

## Сверка с лабораторией

Вкладка «Сверка с лабораторией» сравнивает eGFR, рассчитанную приложением, со значением, которое лаборатория напечатала в бланке. Это проверка на реальных данных: совпадает ли наш расчёт с тем, что врач видит в результатах анализов.

**Подготовка выгрузки.** CSV или таблица из Excel с колонками:

| Колонка | Пример | Обязательна |
|---|---|---|
| ID | 17 | нет |
| Возраст | 50 | да |
| Пол | м / ж | да |
| Креатинин | 106 или 1,2 | да |
| Единица | мкмоль/л / мг/дл | нет (выбирается на странице) |
| СКФ лаборатории | 70 или >90 | да |

Шаблон скачивается кнопкой «Шаблон CSV». Выгрузка должна быть обезличенной: без ФИО, ИИН, дат рождения и номеров карт. Файл обрабатывается только в браузере, не сохраняется и никуда не передаётся.

**Что считается.** Для каждой строки — eGFR по CKD-EPI 2009 и 2021, округлённая до целого (как на экране), и разница «приложение − лаборатория». Сводка по каждой формуле:

- средняя разница и пределы согласия Бленда–Альтмана (± 1,96 SD) с графиком;
- средний и максимальный модуль разницы, доля строк с разницей в пределах ±1, ±3, ±5 мл/мин/1,73 м²;
- совпадение стадии С1–С5, матрица «лаборатория × приложение» и каппа Коэна;
- значения «>90», «>60» не входят в статистику разницы, но проверяются: eGFR приложения должна быть не ниже порога.

Формула с меньшим расхождением отмечается как «ближе к лаборатории» — так видно, по какой формуле считает лаборатория. Строки с разницей больше заданного порога или с другой стадией выводятся списком; полный построчный отчёт — «Отчёт CSV».

**Как читать результат.** Если лаборатория считает по той же формуле, ожидаемая разница — в пределах ±1 (округление). Систематический сдвиг обычно означает другую формулу, другой коэффициент пересчёта единиц, округление креатинина в бланке или расовый коэффициент CKD-EPI 2009 в настройках лаборатории. Единичные большие расхождения — повод проверить строку выгрузки.

Сверка показывает согласие с конкретной лабораторией, а не клиническую точность формулы. По результату можно писать «результаты сверены с лабораторией X на N анализах, максимальная разница Y»; заявлять на этой основе о клинической точности программы нельзя.

- **Совпадение с расчётом авторов.** CKD-EPI 2009 приложения совпала с eGFR, которую рассчитали авторы, в 98 строках из 100 (до 0,05). В двух оставшихся строках ошибка в таблице авторов. Стадии совпали в 100% строк.
- **Точность против измеренной СКФ (n = 98).** Смещение CKD-EPI 2009 — +3,9, P30 — 81,6%, стадия совпала в 66,3% случаев. У CKD-EPI 2021 — +7,2, 80,6% и 65,3%.
- **Ограничения выборки.** Выборка маленькая, участники здоровые, СКФ почти у всех не ниже 45. Показатели точности нельзя переносить на пациентов в Казахстане.

## Ограничения

- Приложение не выводит дозы препаратов: только пороги СКФ и формулировки «коррекция дозы», «рассмотреть», «рекомендуется отмена, требует оценки врачом».
- По однократному измерению диагноз не ставится; результат сопровождается пояснением, что для диагноза ХБП нужно сохранение изменений не менее 3 месяцев.
- Расчёт не выполняется для пациентов младше 18 лет.
- Расовые и этнические категории не используются.
- Используются только источники И1–И8.

## Тесты

`npm test` запускает тесты из `tests/`:

- эталонные значения раздела 13 (допуск ±1), включая расчёт по скорректированной массе;
- границы стадий, альбуминурии (в мг/г и мг/ммоль), таблица риска и сроков контроля;
- граничные значения правил: ОПП (ровно 26,5 мкмоль/л за 48 ч, ×1,5 на 7-е и 8-е сутки), удвоение, госпитализация, метформин 60/59/45/44/31/30/29, иНГЛТ-2 20/19, мочевина и креатинин при пневмонии;
- сценарии групп и динамики, ввод задним числом;
- проверка ввода, экспорт CSV;
- сверка с лабораторией: разбор CSV (разделители, заголовки, «>90», ошибочные строки), разница и пределы согласия, совпадение стадий, каппа Коэна, отчёт;
- конфиг: соответствие id кода и JSON, источники И1–И8, статусы, отсутствие доз, категоричных назначений и расовых категорий;
- открытые данные с измеренной СКФ (Киншаса, иогексол): совпадение CKD-EPI 2009 с расчётом авторов и закреплённые показатели точности;
- соответствие таблиц правил в этом README конфигу;
- подтверждения: официальные PDF источников, существующие номера страниц, связь страницы с источником правила;
- самопроверка страницы «О программе»: все проверки проходят, а с намеренно искажёнными порогами (граница С1, порог ОПП) — падают; в коде интерфейса нет внешних ссылок, кроме репозитория (ссылки на PDF источников — только в `src/config/evidence.ts`).

Самопроверка подтверждает, что программа считает по заявленным формулам и правилам без ошибок реализации. Клиническую точность формул для конкретного пациента она не подтверждает.
